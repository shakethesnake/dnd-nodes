# Example 2: Conditional Connection with Validation

## Описание

Этот пример демонстрирует возможность создания **условных соединений** между нодами с **валидацией** и **визуальной обратной связью**.

## Что реализовано

### Структура графа

**Верхний ряд (3 ноды):**
- Node 1 (зеленая) → Node 2 (синяя) - изначально соединены анимированным edge
- Node 3 (фиолетовая) - изначально не соединена
- Все edges между ними анимированные (flowing particles)

**Нижний ряд (2 ноды):**
- Node 4 (оранжевая)
- Node 5 (красная)
- Изначально не соединены

### Правило валидации

**Node 4 и Node 5 могут соединиться ТОЛЬКО ЕСЛИ Node 2 и Node 3 уже соединены!**

### Визуальная обратная связь

При неудачной попытке соединения:
- Целевой порт **подсвечивается красным** на 0.5 секунды
- В лог выводится сообщение об ошибке с причиной
- Соединение **не создается**

## Что проверяется в примере

### ✅ 1. Условное соединение нод
- Соединение зависит от состояния других нод в графе
- Демонстрирует сложные зависимости между элементами

### ✅ 2. Вычисления перед соединением
- Функция `canConnect` вызывается **перед** созданием соединения
- Возвращает `true`/`false` на основе анализа текущего состояния графа
- Показывает, как выполнять проверки и вычисления для принятия решений

### ✅ 3. Визуальный фидбек
- Красная подсветка порта при ошибке (0.5 сек)
- Анимированные edges для визуализации потоков данных
- Event log с историей всех попыток соединения

## Как тестировать

1. **Запустите приложение**
   ```bash
   npm run dev
   ```
   Откройте http://localhost:5174/

2. **Попробуйте соединить Node 4 → Node 5**
   - Потяните от output порта Node 4 к input порту Node 5
   - ❌ Порт подсветится красным
   - ❌ В логе появится: "Node 2 and Node 3 must be connected first!"
   - ❌ Соединение НЕ создастся

3. **Соедините Node 2 → Node 3**
   - Потяните от output порта Node 2 к input порту Node 3
   - ✅ Соединение создастся (анимированный edge)

4. **Снова попробуйте соединить Node 4 → Node 5**
   - Теперь условие выполнено
   - ✅ Соединение успешно создастся
   - ✅ В логе появится: "Connected node-4:out → node-5:in"

## Технические детали

### Функция валидации

```typescript
const canConnect: CanConnectFn = ({
    sourceNodeId,
    targetNodeId,
    // ...
}) => {
    // Проверяем, это попытка соединить Node 4 и 5?
    const isNode4or5Connection =
        (sourceNodeId === "node-4" && targetNodeId === "node-5") ||
        (sourceNodeId === "node-5" && targetNodeId === "node-4");

    if (isNode4or5Connection) {
        // Проверяем: соединены ли Node 2 и Node 3?
        const isNode2And3Connected = edges.some(
            (edge) =>
                (edge.sourceNode === "node-2" && edge.targetNode === "node-3") ||
                (edge.sourceNode === "node-3" && edge.targetNode === "node-2")
        );

        // Если НЕ соединены - запрещаем
        if (!isNode2And3Connected) {
            highlightErrorPort(targetNodeId, targetPortId || "in");
            return {
                allowed: false,
                reason: "Node 2 and Node 3 must be connected first!",
            };
        }
    }

    return { allowed: true };
};
```

### Подсветка порта

```typescript
// Добавляем порт в Set ошибочных портов
const highlightErrorPort = (nodeId: string, portId: string) => {
    const key = `${nodeId}-${portId}`;
    setErrorPorts(prev => new Set(prev).add(key));

    // Через 500ms автоматически удаляем
    setTimeout(() => {
        setErrorPorts(prev => {
            const next = new Set(prev);
            next.delete(key);
            return next;
        });
    }, 500);
};
```

## Применение в реальных проектах

Этот паттерн полезен для:

### 1. **Workflow системы**
- Шаг B может выполниться только после завершения шага A
- Контроль последовательности выполнения операций

### 2. **Валидация типов данных**
- Проверка совместимости типов перед соединением
- Например: "Number" ноды могут соединяться только с "Number" или "Any" нодами

### 3. **Системы авторизации**
- Доступ к определенным нодам только после выполнения условий
- Например: премиум-функции доступны только платным пользователям

### 4. **Игровая логика**
- Открытие новых путей после выполнения квестов
- Прогрессия игрока через уровни

### 5. **Data Pipeline**
- Проверка наличия всех необходимых источников данных
- Валидация схемы данных перед трансформациями

## Ключевые возможности библиотеки

✅ **ConnectionProvider** - управление логикой соединений
✅ **canConnect** - кастомная валидация перед соединением
✅ **Event Handlers** - отслеживание жизненного цикла соединений
✅ **AnimatedEdge** - визуально привлекательные анимированные edges
✅ **Custom Nodes** - полный контроль над внешним видом и поведением нод
